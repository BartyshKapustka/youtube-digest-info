Privacy policy

This policy covers YouTube Digest, a personal automation operated by Egor Tulyakov. The application is intended for the operator’s own Google account.

Data accessed and collected

With authorization through Google OAuth, the tool uses the youtube.readonly scope to read subscribed channel identifiers, names and URLs, and metadata for public videos, including video identifiers, titles, publication dates, duration, category and live status. It also collects transcripts for selected public videos, processing status, errors and service usage records. OAuth credentials and refresh tokens enable unattended access.

The current implementation does not request Gmail, Google Contacts or Google Drive access. It does not deliberately retrieve private videos or watch history. The operator’s Google password is not collected.

Purpose and use

Data is used to synchronize subscriptions, select relevant videos, avoid duplicate processing, obtain transcripts, track errors and costs, and prepare personal video summaries. The application does not sell data, use it for advertising, or use it to develop or train a generalized AI model. YouTube Digest’s use and transfer of information received from Google APIs will adhere to the Google API Services User Data Policy, including the Limited Use requirements.

Storage and service providers

  • Google / YouTube: provides authorization, subscription data and video metadata.
  • GitHub: runs the collection workflow and stores subscription records, transcripts and processing records in a private repository. Long-lived application credentials and refresh tokens are stored as GitHub Actions secrets; temporary access tokens are used during execution.
  • Apify: receives identifiers or URLs of selected public videos to obtain transcripts. The collection code does not send Google OAuth credentials or the complete subscription list to Apify. Provider runs and datasets may retain submitted video identifiers and transcript results under Apify’s own settings and policies.
  • OpenAI / ChatGPT: the connected scheduled task reads selected transcript and metadata files to generate and deliver summaries. Processing and retention by ChatGPT depend on the operator’s account settings and OpenAI’s policies. This project does not promise provider-level training exclusions beyond those settings and policies.

The public information site does not include Google credentials, subscription lists or collected transcripts. It has no application sign-in, analytics scripts or advertising trackers. GitHub Pages may process request information under GitHub’s privacy statement.

Retention

Subscription records are updated on successful synchronization. The collector removes older video entries from the current manifest after approximately 14 days based on publication date, but transcript files and earlier Git history are not automatically deleted by that step. Secrets remain until removed or replaced. GitHub history, Apify datasets and ChatGPT conversations may retain earlier copies; revoking access does not erase these copies.

Revoke access and delete data

To stop future collection, disable the GitHub Actions workflow and the scheduled ChatGPT task. Revoke the application’s access in Google Account connections, and remove its OAuth secrets from GitHub. To remove stored data, delete the relevant subscription records, transcripts and manifests from GitHub, address historical copies in Git history where needed, remove Apify runs and datasets, and delete associated ChatGPT conversations or files. Provider backups and logs remain subject to the respective provider’s retention rules.

Contact and changes

For questions or deletion requests, contact the operator through the project’s GitHub issue tracker. Issues are public: do not include credentials, tokens or private account data. This policy will be updated when the application’s data practices change.
